# Toolbox v3.3.0

## What's new

- **Themes.** **Settings → Appearance** now has a theme picker with a live preview in light and dark, next to *Light*, *Dark* and the new *Follow system*. Toolbox ships *Default* and *High contrast*, and you can add your own. A theme is one small data file that changes colours, corner roundness, the font and the accent colour of each menu section. It contains no code, so it is the safest kind of mod: only known colours are accepted (no CSS of any kind), low-contrast text is flagged, and a theme that would make error text or the **Remove** and **Apply changes** buttons hard to read, or turn them a harmless colour, is refused. Install one like any mod (git address, folder, zip, a single `.toml` file, or the market); turning it off, removing it, or starting in safe mode returns to the default look. **Copy as theme file** exports the current look as a starting point, and **Copy AI theme prompt** lets an AI assistant design one from a description. Implements #12.
- **Richer mod forms.** A mod can now group its fields into sections or tabs, show fields only when they matter (`show_if`), and use a slider, a multi-choice list, a colour and a date field. Extra buttons next to Run (for example "Test connection") call a function in the mod, and after a run a mod can show its findings as counters, a table, a file list with **Open** and **Show**, markdown, an image or a note instead of only log lines. All of this is described in `mod.toml` and drawn by Toolbox: no code from a mod runs in the page. More icons are available and a tool can pick its tile colour from the active theme.
- **Mods choose their own category, reliably.** `media`, `Media` and ` Media ` are now the same section. The built-in sections (Files, Media, Subtitles, Experimental, Other) keep a fixed place and a mod's `order` only positions it inside its section, so one mod can no longer push a section around. A new category appears after the built-in ones, and a name that only looks like an existing one (`Subtitle`, `Sub-titles`) is reported instead of quietly making a second section. The category is shown in the install prompt, in **Settings → Mods** and in the market, and the categories are documented in `MODDING.md` and in the AI prompt. Closes #13.
- **Market: tools and themes.** The mod market can be filtered by *Tools* and *Themes*, shows the section of a tool, and shows colour swatches for a theme so it can be judged without installing it. It lists two new examples: **Folder Report** (everything the richer form can do) and **Solarized** (a complete theme).
- **Every colour comes from a theme token.** Group accents, log levels and status colours no longer use fixed colours, so a theme reaches all of them. The look of the default theme is unchanged, apart from slightly darker accents for Experimental and Other in dark mode so the icons on them stay readable.

## Good to know

- The mod API is now version 2. Mods written for version 1 keep working unchanged; a mod that uses anything new has to say `api_version = 2`, and an older Toolbox refuses it with a clear message.
- Mod-supplied HTML or JavaScript panels are not part of this release. Only data is drawn in the page.
- A tool mod is still code that runs with the same access as Toolbox, and mods are not reviewed. Themes are different: they are data.

## Install

Download from [GitHub Releases](https://github.com/MerlijndeVos/Toolbox/releases/tag/v3.3.0):

| Platform | File |
|----------|------|
| Windows | `Toolbox-Setup-3.3.0-win64.exe` |
| macOS | `Toolbox-3.3.0-macos.dmg` |
| Linux | `Toolbox-3.3.0-linux-{arch}.AppImage` |

Installers are **unsigned**. Windows SmartScreen and macOS Gatekeeper may ask you to confirm once (“Run anyway” / “Open”).

**ffmpeg** is not bundled in the installer. On first launch the app downloads a one-time essentials build into your user data folder.

## Updating from v3.2.1

Use **Settings → Updates → Update to v3.3.0** in the desktop app, or download the new installer for your OS from the table above.
